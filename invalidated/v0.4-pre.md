# v0.4-pre — INVALIDATED

**Status:** INVALIDATED. Do not include this run in benchmark conclusions, aggregates, or headline metrics.

## What happened

The diagnostic runner intended for the v0.4 probe accidentally loaded the v0.3 benchmark file. The resulting output therefore did not evaluate the intended v0.4 diagnostic set.

## Why the record is retained

The run is preserved as part of the provenance trail rather than silently deleted. Keeping invalidated experiments visible makes it possible to distinguish:

- a valid result that performed poorly,
- a superseded methodology,
- and a run that never measured what it claimed to measure.

This case is the third category.

## Corrective action

The benchmark-loading error was identified, the diagnostic was corrected, and the valid rerun is recorded as **v0.4**.

The corrected v0.4 run contained 18 cases and produced:

- 13/18 overall accuracy (72.2%)
- 4/9 complete semantic pairs (44.4%)
- durability: 6/6
- filesystem: 4/6
- authorization: 3/6

The valid result reinforced the finding that read-only recognition was weak under the broad multiclass `operation_type` formulation.

## Reporting rule

Invalidated runs remain part of the experiment history but are excluded from valid-result comparisons. Corrections receive a new valid record rather than replacing history in place.
